# Daily catalog reconciliation
- Official reads and FOP applications acquire the shared service-only renewable lease before reading or writing catalog state; ownership tokens fence renew/release and automatic contention arms a bounded retry which drains on acquisition.
- Keep spreadsheet layout, field ownership and three-way comparison in the shared catalog module; never write status/identity fields from this feed; products are born only as v2 proposals confirmed on screen.
- Test reads use isolated reading records and synthetic snapshots, never update the official cell base or live products.
- Microsoft credentials and FOP machine authentication come only from Vault through the service-role client; do not return tokens or raw OAuth errors.
- Product- and fiscal-owned (operacoes) cells are written only in the FOP via `aplicar-fop.ts` (resolver called per owner) (tested with a fake FOP); mark applied only on `aplicada` or a conflict whose current value matches the requested value, and require the pending-response RPC count to match the batch, so already-applied values and partial registrations cannot become false conflicts or silent success; a transport failure applies nothing and records the error on every cell of that batch.
- Catalog v2 spreadsheet export is generated only by the catalogo-planilha-gerar-v2 edge from vw_catalogo_planilha_v2 (HTML→text in _shared/catalogo-planilha/html-texto.ts); it never touches the reading/comparison path.
- v2 "Códigos e EAN" sheet: classification lives only in the tested `nascimento.ts` (stored in `totais.propostas`, nothing written on read); confirmation goes only through `fn_catalogo_nascer_da_planilha` (cartório first, then `fn_nascer_produtos_lote`, atomic, dry-run rolled back), because the code↔EAN pair and inner belong to that sheet, never to the Catálogo tab. Without that sheet the v1 read is unchanged.
- v2 catalog sheet read: columns owned by 'Sistema · consulta' and (v2 only) descricao_produto/meta_descricao are decided by colunasNaoComparadas in comparacao.ts, never compared nor seeded into the base; v2 codes without product feed only birth proposals.
- Read only present comparable fields, with at most three 150-code read batches in parallel; retain stage timings in the reading. Reader leases last 90 seconds with renewal and fenced beforeunload release; interrupted workers must never report provisional errors as finished results.
- Store columns (loja_*) map to `loja_dim.slug_planilha` and compare Sim/Não against `produto_loja.vende` via the tested `lojas.ts`; applying them goes only through `fn_catalogo_aplicar_lojas` (never the FOP), and `canal_venda` is derived from produto_loja by trigger (read-only in the sheet), because store membership belongs to the SNCF, not the FOP.
